## The lesson

Lesson 23 left a question for the next Part V seam: *what is the scope of the
thing you just named, and is the checker allowed to see all of it?* Lesson 24 is
the seam that answers it in the one way the first six could not, which is why it
is worth a lesson rather than a footnote.

The scope is **one node**. The reader may see all of it — every prop, every
child, nothing in another party's registry, nothing withheld. And it still
cannot answer, because what is missing is not a piece of the tree. `value` and
`align` are the same JSON, and which of them is a word a reader reads is a fact
about the *component*, not about the data.

So Part V gets a second axis. The first six seams are about a checker that
cannot see enough; this one is about a checker that sees everything and cannot
interpret it. The README's Part V paragraph now says that, and the question
carried forward is the one this lesson's finding is an instance of: **when your
system cannot answer, what does it return — and who would notice if it started
returning that when it could?**

What I emphasised, in order of how much I would defend it:

1. **The design question is not how a primitive declares, it is what a reading
   says about the primitive that has not.** On the day a seam like this ships,
   nothing has declared, so the *absence* case is the whole product. Answer it
   with "no words" and you have rebuilt the original bug one level along, with a
   mechanism in front of it making it look answered. This is the spine of the
   lesson and it is what Predict 2 is for.
2. **Empty and absent are different answers, and keeping them apart costs the
   answer its shape.** `copyIn` returns words *and* `unread`. Exercise A prints
   the two readings that have identical `words` and opposite meanings, six lines
   apart, which is the cheapest possible demonstration that one list would not
   have been enough.
3. **Three seams, one rule.** Lesson 15's conformance probe (0090), the pairings
   probe (0113) and this one all refuse to round *I could not tell* into *there
   are none*. Stating it as a rule — a measurement that cannot be taken is not a
   measurement of zero — is the transferable half, and it is what Set AC's
   question 3 asks for without the vocabulary of any of the three.
4. **A misspelling is refused rather than read as silence**, which generalises to
   the thing I would most want a reader to take away: any channel with a "nobody
   said" value has to make it impossible to reach that value by accident.
5. **Replacing a correct guess with an authoritative source is a regression
   until the authority has been told.** Exercise G prints all three readings —
   the hard-coded array, the registry against a host that declared, and the
   registry against this repository — and the third is `"Untitled page"`. The
   general form is worth more than the instance, and I said so rather than
   leaving it as a Loom fact.

## Found while teaching

**A copy prop whose value is not a string vanishes from both halves of
`copyIn`'s answer.** Filed for `Loom daily build`; `src/sdk/` is that lane's.

Exercise C was written to show the decided behavior — a non-string value is
skipped, never coerced, because a wrong word is worse than a missing one — and
the run showed something the record does not cover:

```
  value: 3400, declared
    words:  ["appointments"]
    unread: none
```

Two rules compose into a hole. `declaredWords` skips the non-string, correctly.
`unread` reports only types that declared *nothing*, correctly. A type that
**did** declare and holds a number loses the word and reports nothing — which is
exactly the failure the return type's second field exists to prevent. The
undeclared side has the same hole from the other end: `stringProps` filters
non-strings too, so `unread` names `["label"]` and never mentions `value`.

It is reachable where this seam is used rather than only in principle: the two
callers 0122 was filed for read a queue row about a proposal and a preview of a
node nobody has approved, which is precisely where props have not met a schema.
`copy.test.ts:156` pins `words` for this case and asserts nothing about `unread`,
so the silence is tested in rather than missed.

I deliberately did not propose the obvious fix as though it were obvious. Naming
the prop in `unread` would make one field mean two things, which is this seam's
own complaint about defaults, and it would change what an empty `unread` asserts
for every existing caller. The finding says that and leaves the shape to the lane
that owns it.

## What the exercises found about the exercises

Two things the run corrected before anything was written down.

**Exercise B was originally a non-experiment.** It contrasted a registry where
the stat "had declared" against one where it had not — and the nodes in both were
`demo.quiet-stat`, so both readings were identical and the transcript proved
nothing while looking like it proved everything. Rebuilding it as two grids of
the same three figures under two different types is what makes the contrast real,
and it picked up a better third fact on the way: the grid declares `copy: []` and
is therefore *absent* from `unread` in both readings, which is the clearest
demonstration of "empty is believed" in the lesson.

**Exercise F's node ids read `n_6, n_5, n_1 … n_4`.** The section has the highest
id and comes first, because children are built before the parent that takes them.
That is lesson 23's exercise C arriving unbidden in a transcript about something
else entirely, and I left it in with a sentence pointing at it rather than tidying
the fixture.

The Try it program is **byte-identical** to the file that produced the
transcripts — checked by extracting the eight `ts` fences from the section,
concatenating them in document order, and diffing against the scratch file
(identical but for a trailing newline). Every line of all eight plain fences was
then checked against the real output with the same rule `transcripts.test.ts`
uses: **8 recognised, 0 drifted.** `src/scratch.test.ts` is deleted.
